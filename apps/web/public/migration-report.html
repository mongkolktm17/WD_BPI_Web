3 จุดที่ต้องแก้ก่อนวันย้าย (Critical Gaps)

1

Parking Lot Counts ไม่ถูกบันทึก

ในหน้า apps/web/app/car-parking/page.tsx — ฟอร์มเก็บค่า carLotCounts และ motoLotCounts ไว้ใน state แต่ตอน handleSubmit ไม่ได้ส่งค่าเหล่านี้ไป API ทำให้ จำนวนรถต่อลานจอดไม่ถูกบันทึกเลย

สิ่งที่ต้องแก้:
  • เพิ่ม carLotCounts และ motoLotCounts ใน POST body
  • Backend NestJS: บันทึกลง ParkingLotCount model ( Prisma schema มีแล้ว)
  • ตรวจสอบว่า dashboard ดึงค่า lot counts ได้ถูกต้อง
2

Edit Reports ใช้ได้แค่ Building Reports

ในหน้า apps/web/app/report-page/page.tsx — ReportDetailModal แสดงข้อความ "ไม่สามารถแก้ไขรายละเอียดได้ในโหมดนี้" สำหรับ 8 ประเภทรายงาน (car_parking, cctv_inspection, hand_held, patrol, guard_count, cctv_report, cctv_angle, metal_detector)

สิ่งที่ต้องแก้:
  • สร้าง editable form ใน ReportDetailModal สำหรับทุกประเภท
  • Backend PUT endpoints มีอยู่แล้วส่วนใหญ่ — เหลือแค่ frontend
  • หรือสร้างหน้า edit แยกสำหรับแต่ละประเภท
3

Hard Delete แทน Soft Delete

ระบบเดิมใช้ is_deleted = 1 (soft delete) — ข้อมูลไม่หาย แต่ระบบใหม่ใช้ Prisma delete() ทำให้ ข้อมูลหายถาวร

สิ่งที่ต้องแก้:
  • เพิ่ม isDeleted Boolean @default(false) ในทุก Prisma model ที่เกี่ยวข้อง
  • แก้ DELETE endpoints ทั้งหมดเป็น update({ data: { isDeleted: true } })
  • แก้ GET/findMany ทั้งหมดเพิ่ม where: { isDeleted: false }
  • ทำ Prisma migration ใหม่
4

ไม่มีหน้า Profile + เปลี่ยนรหัสผ่าน

ระบบเดิมมีหน้า update_profile.php ให้แก้ไขข้อมูลส่วนตัวและเปลี่ยนรหัสผ่าน ระบบใหม่ยังไม่มีหน้า UI สำหรับส่วนนี้ และ backend ยังไม่มี endpoint เปลี่ยนรหัสผ่าน

สิ่งที่ต้องแก้:
  • สร้างหน้า Profile ใน frontend (แก้ไข name, phone, email)
  • เพิ่ม PUT /api/auth/change-password (verify current password → set new)
  • เพิ่ม PUT /api/users/profile (email, phone fields)

📋 ขั้นตอนการย้ายข้อมูล (Data Migration Steps)

1
สร้าง Prisma Schema ให้ครบ
เพิ่ม CctvDevice, CctvCameraName models ที่ยังขาด + isDeleted field ทุก model
2
สคริปต์ ETL (Extract-Transform-Load)
เขียน Node.js script เชื่อม MySQL → PostgreSQL: users, roles, reports, parking, cctv, detectors, patrol
3
Import ข้อมูลผู้ใช้ + Role mappings
users → User, roles → Role, role_permissions → RolePermission (map page_name → moduleName + canRead/Write/Delete)
4
Import ข้อมูลรายงานทั้งหมด
reports → BuildingReport, car_parking_reports → CarParking, cctv_inspections → CctvInspection, hand_held_checks → HandheldCheck, metal_detector_checks → WalkthroughCheck, patrol_reports → PatrolReport, security_guard_counts → GuardCount
5
Verify + Smoke Test
ตรวจนับจำนวนรายการในแต่ละตาราง, ทดสอบ login ด้วย user เดิม, ตรวจสอบ dashboard data
⚠️ สิ่งที่ต้องระวังในการย้ายข้อมูล
  • Thai text encoding — ต้องใช้ UTF-8 ทั้ง MySQL และ PostgreSQL
  • Bcrypt password hashes — ใช้ได้เหมือนเดิม (ไม่ต้อง rehash)
  • Foreign key relationships — ต้อง import ในลำดับที่ถูกต้อง (roles → users → reports)
  • Auto-increment IDs — ต้อง reset sequences ใน PostgreSQL หลัง import
  • cctv_devices + cctv_camera_names — ตารางอุปกรณ์ ต้องสร้าง schema ใน Prisma ก่อน import

7 ความเสี่ยง (Risk Assessment)

ความเสี่ยง ระดับ ผลกระทบ แผนรับมือ
Parking data หาย สูง รายงาน parking ไม่มีข้อมูลต่อลาน แก้ form + API ก่อนย้าย
Hard delete ข้อมูล สูง ข้อมูลรายงานหายถาวร ไม่สามารถกู้คืนได้ แก้เป็น soft delete ก่อนย้าย
Thai encoding ผิด กลาง ข้อมูลภาษาไทยเพี้ยน ใช้ UTF-8 ทั้งหมด + ทดสอบ encoding
Password hash ไม่เข้ากัน ต่ำ User เดิม login ไม่ได้ bcrypt ใช้ได้เหมือนกัน — ทดสอบก่อน
Missing edit forms กลาง แก้ไขรายงานไม่ได้ ต้องลบแล้วสร้างใหม่ สร้าง edit forms ให้ครบก่อนย้าย
Downtime ระหว่างย้าย กลาง ผู้ใช้เข้าระบบไม่ได้ชั่วคราว ทำ delta sync ตอน off-hours, downtime < 30 นาที
